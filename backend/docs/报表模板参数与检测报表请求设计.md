# 报表模板参数与检测报表请求设计

## 目标

客户的报表需求不是固定字段：有的报表没有参数，有的报表需要公式输入参数；多数场景是一份报表对应一个变量，也可能一份报表引用多个变量和多个参数。Excel 公式固定在报表模板里，边缘端不解析公式，只保存主服务器生成报表所需的快照。

本设计避免把客户需求写死到 `ext_1/ext_2/ext_3` 这类固定列里。后端提供稳定结构，变化交给模板参数 schema 和每次检测的报表请求 JSON。

## 数据模型

### `sys_report_templates.params_schema_json`

报表模板声明自己需要哪些公式输入参数。它是 JSON 对象或数组，由前端动态表单和主服务器 Excel 填充逻辑共同使用。

示例：

```json
[
  {
    "key": "inlet_area_m2",
    "label": "进风口面积",
    "type": "number",
    "unit": "m2",
    "required": true,
    "excel_name": "InletArea"
  },
  {
    "key": "remark",
    "label": "备注",
    "type": "text",
    "required": false,
    "excel_name": "ReportRemark"
  }
]
```

`excel_name` 表示主服务器生成 Excel 时写入的命名区域或模板映射键。公式仍保留在 Excel 模板中。

### `detection_run_report_requests`

一行表示一次检测里要生成的一份报表，不再表示“一个变量一行”。核心字段：

- `template_id/template_code/template_version`：本次报表使用的模板快照。
- `variables_json`：这份报表引用的变量数组，可为一个或多个变量。
- `params_json`：这份报表本次填写的公式输入参数。
- `report_name/status`：主服务器处理和页面展示使用。
- `var_id/var_name/display_name*`：保留为第一变量摘要，便于筛选和兼容旧页面。
- `ext_1/ext_2/ext_3`：历史兼容字段，不再作为新需求扩展入口。

示例：

```json
{
  "template_code": "PERFORMANCE_REPORT",
  "report_name": "性能报表",
  "variables": [
    {"var_id": "1001", "var_name": "air_volume"},
    {"var_id": "1002", "var_name": "power"}
  ],
  "params": {
    "inlet_area_m2": 1.25,
    "ambient_temp": 23.5
  }
}
```

## 检测启动请求

推荐新格式：

```json
{
  "report_request": {
    "reports": [
      {
        "template_id": 3,
        "report_name": "出风温度报表",
        "variables": [{"var_id": "1001"}],
        "params": {"remark": "标准工况"}
      },
      {
        "template_code": "PERFORMANCE_REPORT",
        "variables": [{"var_name": "air_volume"}, {"var_name": "power"}],
        "params": {"inlet_area_m2": 1.25}
      }
    ]
  }
}
```

兼容旧格式：

```json
{
  "report_request": {
    "var_ids": ["1001", "1002"],
    "ext_1": "旧备注"
  }
}
```

旧格式仍会生成多条报表请求，每条请求只含一个变量；新需求应使用 `reports[]`。

## 参数边界

- `params_schema_json`：模板需要什么公式输入参数。
- `params_json`：某次检测中某份报表实际填写的公式输入值。
- `variables_json`：某份报表引用哪些变量。
- `process_params`：检测过程、PLC 下设、过程计算需要的参数。
- `operator_note`：人可读备注，不作为结构化报表参数。
- `custom_items`：检测标准项，不放报表参数。

如果某个值既要下设 PLC 又要进报表，前端可以只让用户填一次，然后同时映射到 `process_params` 和对应报表请求的 `params`，或后续用任务参数绑定规则统一生成。

## 前端适配

前端需要按模板渲染报表请求：

1. 用户选择一个或多个报表模板。
2. 读取每个模板的 `params_schema_json`，生成参数表单。
3. 每份报表选择一个或多个变量。
4. 检测开始前可填写；检测结束后生成报表前也可补充或修改。
5. 请求保存为 `report_request.reports[]`，不要继续用 `ext_1/ext_2/ext_3` 作为新参数入口。

## 主服务器消费

主服务器通过数据库同步看到 `detection_run_report_requests` 后：

1. 按 `task_id/test_no/project_id` 找到检测任务和历史数据。
2. 按 `template_id/template_code/template_version` 找模板。
3. 按 `variables_json` 取变量历史、特征值、报警和摘要。
4. 按 `params_json` 填入模板命名区域或映射键。
5. Excel 公式由模板自身计算。

边缘端只负责冻结请求快照，不实现 Excel 填充引擎。
