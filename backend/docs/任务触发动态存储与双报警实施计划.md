# 任务触发、动态存储与双报警实施计划

## 背景

本计划承接当前实时底座、检测任务、业务超限报警和变量默认报警字段地基。目标不是继续把逻辑堆进采集链路，而是把采集后的业务拆成独立引擎：

- 任务触发：参考 JGHJ 的变量触发任务思想，但用倒排索引实现。
- 动态存储：按项目设备分宽表，支持动态表单字段和自动扩列。
- 检测业务报警：服务于一次检测任务，支持业务上下限、周期、首帧判断、静音和后续等级变化。
- 变量默认报警：变量级自动报警，独立于检测任务，不包含静音。
- WS/下设：通过后端 service 和审计日志进入，不绕过后端直写 MQTT/KIO。

## 总体链路

```text
MQTT/KIO
  -> 已知变量过滤
  -> 清洗层
  -> GlobalTagMap
  -> ProjectRealtimeView
  -> TaskTriggerEngine
  -> StorageEngine
  -> DetectionAlarmEngine
  -> DefaultAlarmEngine
  -> WS/HTTP 查询
```

热路径原则：

- MQTT callback 只入队，不写库。
- 清洗层只做类型转换、系数、偏移、防抖、死区、质量戳和稳定值更新。
- `GlobalTagMap` 不保存检测上下限、不保存存储路由、不保存报警配置。
- 任务触发、存储、检测报警、默认报警都从内存索引读取快照，不在每次变量变化时查数据库。
- 自动建表和自动扩列只能发生在配置保存、检测启动或显式 schema 准备接口中，不能发生在采集写入热路径。

## 业务拆分

### 任务触发系统

参考 JGHJ 的变量触发任务能力，但不能用扫描式脚本。后端应维护倒排索引：

```text
var_id -> rule_ids
```

变量变化时只评估相关规则：

```text
TagChanged(var_id)
  -> TaskRuleIndex.Lookup(var_id)
  -> Evaluate(rule_ids)
  -> Execute actions
```

首批规则能力：

- 单变量条件：`var == value`、`var != value`、`var > value`、`var < value`。
- 边沿触发：例如 `0 -> 1` 才触发检测开始。
- 多变量组合：同一设备实时视图中多个变量同时满足条件。
- 幂等保护：同设备已有 running 检测任务时不重复启动。
- 动作类型：启动检测、停止检测、异常停止、写虚变量、写审计事件。

任务触发层只触发业务动作，不直接写历史、不直接判断报警。

检测开始变量示例：

```text
检测开始变量 0 -> 1
  -> TaskTriggerEngine
  -> DetectionRunsService.Start(...)
  -> 生成检测运行快照和存储路由快照
```

### 动态存储系统

本项目要求按项目设备分表，并使用宽表承载动态表单数据。现有 `rt_history_data` 窄表保留为兼容和调试路径，不再作为本项目主存储模型。

设计审查修正：变量属性里不再放有效存储频率、变化存储死区、目标表或目标列。`sys_tags.store_*` 和 `sys_tags.storage_*` 只保留兼容，不再进入存储热路径。所有有效存储配置必须来自 `sys_storage_routes`，包括目标表、目标列、周期、变化死区、首帧存储和是否启用。

默认设备宽表命名：

```text
rt_project_{project_id}_data
```

固定列：

```text
id
task_id
test_no
project_id
project_code
sample_time
sample_bucket_ms
created_at
updated_at
```

用户也可以在 `sys_storage_routes.table_name` 中选择后端校验过的自定义目标表；默认设备宽表只是默认建议，不是唯一合法目标。动态列来自受控字段名，不使用设备名、变量显示名或前端任意字符串直接拼 SQL。候选来源：

- `form_field_key`
- `query_alias`
- `storage_value_column`

后端必须做列名规范化和唯一性校验。

新增配置表：

```text
sys_storage_routes
```

建议字段：

```text
id
project_id
var_id
route_code
storage_target
table_name
column_name
column_type
form_field_key
query_alias
trigger_mode
cycle_ms
deadband
store_on_start
enabled
created_at
updated_at
```

检测启动时冻结到：

```text
detection_run_storage_routes
```

建议字段：

```text
id
task_id
test_no
project_id
var_id
route_id
route_code
storage_target
table_name
column_name
column_type
form_field_key
query_alias
trigger_mode
cycle_ms
deadband
store_on_start
created_at
```

存储运行态：

```text
StorageEngine
  -> 按 detection_run_storage_routes 判断是否需要存
  -> 不回读变量级 store_cycle_sec/store_deadband/store_mode/store_trigger
  -> 生成 StorageIntent
  -> StorageDispatcher 按设备表和时间桶合并
  -> ProjectWideTableWriter 批量 upsert
```

`StorageIntent` 不直接等于数据库行，建议结构：

```text
task_id
test_no
project_id
project_code
sample_time
sample_bucket_ms
values: column_name -> typed value
```

写入方式：

- 同一设备、同一任务、同一时间桶合并为一行。
- 宽表唯一键建议先用 `(task_id, sample_bucket_ms)`。
- 变量周期不同会产生稀疏宽表，这是可接受的；未到周期的列不更新。
- `store_on_start` 控制检测开始首帧存储。

Schema 准备：

```text
检测启动
  -> 冻结 storage routes
  -> SchemaManager.EnsureProjectWideTable(project_id, routes)
  -> 缺表 CREATE TABLE
  -> 缺列 ALTER TABLE ADD COLUMN
  -> 启动任务
```

### 检测业务报警

检测业务报警服务于某次检测任务，读取：

```text
detection_run_standard_items
```

已完成：

- `enter`
- `recover`
- `detection_limit_alarms`
- `Alarm` 队列批量入库
- 首帧判断 `check_on_start`
- 周期判断 `check_cycle_ms`
- 520 变量 10 分钟压测

待补：

- `level_change`，例如 H 升 HH、LL 回 L。
- 检测业务静音。
- 运行中标准调整事件。
- 前端报警状态与摘要展示。

静音只属于检测业务。语义：

- 用户点击静音时，记录当前任务内已经处于报警状态的业务报警项。
- 这些项持续报警期间不再提醒。
- 新增报警仍提醒。
- 已恢复后再次报警仍提醒。
- 静音不修改变量默认报警配置。

### 变量默认报警

变量默认报警是变量资产级自动报警，不依赖检测任务，不带静音。

当前已完成字段地基：

- `default_alarm_enabled`
- `default_limit_ll/default_limit_l/default_limit_h/default_limit_hh`
- `default_limit_deadband`
- `default_violation_hold_ms/default_recover_hold_ms`

待补：

- 默认报警运行态状态机。
- 默认报警独立记录表，例如 `default_limit_alarms`。
- 默认报警 enter/recover 入库。
- 默认报警与检测业务报警并行运行的端到端测试。

默认报警不应写入 `detection_limit_alarms`，避免和检测任务报警混淆。

### 计算变量

计算不放进 storage writer。后续新增 `ComputeEngine`：

```text
原始变量 A/B/C
  -> ProjectRealtimeView
  -> ComputeEngine
  -> 派生变量 X
  -> StorageEngine / DetectionAlarmEngine / WS
```

计算结果应作为虚拟或派生变量进入运行态，并通过同一套 storage routes 存储。

## 实施阶段

### P0 文档和看板冻结

输出：

- 本计划文档。
- `AI_BOARD.md` 新增后续 EB 项。
- `MEMORY.md` 记录边界：任务触发、动态存储、检测报警、默认报警分离。

验证：

- 文档审阅，不改代码，不跑 Go 门禁。

### P1 存储路由模型

后端改动：

- 新增 `sys_storage_routes`。
- 新增 `detection_run_storage_routes`。
- `AutoMigrate` 和 `backend/deploy/schema.sql` 同步。
- Repository 增加 storage route CRUD、冻结、查询方法。
- 变量现有 `storage_*` 字段保留为默认值和兼容字段。

测试：

- 创建变量后生成默认 storage route。
- 一个变量可有多条 route。
- 禁止非法表名、非法列名、重复列名。
- 检测启动冻结 routes。
- 已冻结 routes 不受后续配置修改影响。

### P2 设备宽表 SchemaManager

后端改动：

- 新增 `ProjectWideTableSchemaManager`。
- 检测启动前确保设备宽表存在。
- 根据 routes 自动扩列。
- DDL 只走低频路径。

测试：

- 设备首次检测自动建 `rt_project_{project_id}_data`。
- 新增 route 后再次检测自动扩列。
- 已存在列不重复 ALTER。
- 非法列名被拒绝。
- 并发启动同设备仍由现有设备行锁保护。

### P3 StorageIntent 和宽表 writer

后端改动：

- 将现有 `StoreTask` 升级或旁路为 `StorageIntent`。
- `StorageEngine` 按运行 storage routes 判断存储。
- `StorageDispatcher` 按设备表和时间桶合并。
- `ProjectWideTableWriter` 批量 upsert。
- `rt_history_data` 保留兼容 writer，默认本项目走宽表 writer。

测试：

- 检测开始首帧按 `store_on_start` 写宽表。
- 周期存储按 route `cycle_ms` 写宽表。
- 变化存储按 route `deadband` 写宽表。
- 同一时间桶多变量合并到同一行。
- 不同设备写入不同设备表。
- 520 变量压测对比队列深度和写入延迟。

### P4 历史查询适配宽表

后端改动：

- `GET /api/v1/history/data` 保持兼容。
- 新增或扩展查询路径，根据设备和 routes 从宽表读取。
- 返回 DTO 保持前端可消费；必要时新增字段说明数据来源。

前端事项：

- 历史查询页支持设备宽表结果。
- 动态表单字段按 route 元数据显示。

测试：

- 按 `project_id/task_id/test_no/time` 查询宽表。
- 查询结果能还原变量列和值。
- 旧 `rt_history_data` 查询不被破坏。

### P5 任务触发倒排索引

后端改动：

- 新增任务规则表，例如 `sys_task_rules`、`sys_task_rule_conditions`、`sys_task_rule_actions`。
- 新增运行态 `TaskRuleIndex`：`var_id -> rule_ids`。
- 数据变化后只评估相关 rule。
- 动作先接入检测开始/停止。

测试：

- 单变量 `0 -> 1` 启动检测。
- 同设备重复触发不重复创建任务。
- 多变量组合条件只在全部满足时触发。
- 修改规则后重载倒排索引。
- 高变量量下确认不全量扫描。

### P6 检测业务静音和 level_change

后端改动：

- 检测任务运行态维护静音集合。
- 新增静音 API 或 WS command。
- `detection_limit_alarms` 或附表记录静音状态和操作审计。
- 补 `level_change` 状态机。

测试：

- 静音时已有报警不再提醒。
- 新增报警仍提醒。
- 恢复后再次报警仍提醒。
- H -> HH 产生 `level_change`。
- HH -> recovered 正确关闭。

### P7 默认报警闭环

后端改动：

- 新增默认报警表，例如 `default_limit_alarms`。
- 新增 `DefaultAlarmEngine`。
- 根据变量默认上下限和保持时间维护 enter/recover。
- 默认报警不带静音，不写检测业务报警表。

测试：

- 默认报警开启后变量超限写默认报警表。
- 默认报警恢复关闭。
- 默认报警关闭时不判断。
- 默认报警和检测业务报警同时存在时分别入表。

### P8 前端适配

前端事项：

- 存储路由配置 UI：变量可配置多条 route。
- 动态表单字段配置 UI：列名、类型、显示名、是否启用。
- 检测任务详情展示 storage route 快照。
- 历史查询展示设备宽表数据。
- 检测业务报警静音入口。
- 默认报警和检测业务报警分开展示。
