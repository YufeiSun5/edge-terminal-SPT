# 前端接口：站点与变量发现

本文只覆盖当前阶段前端需要的底层接口：站点/MQTT源配置、变量发现、变量属性维护、连接状态查看。

暂不包含清洗、防抖、热冲裁业务。检测标准配置接口已在当前版本提供给前端配置页预接入。

## 1. 连接状态

### GET `/health`

用途：桌面端首页健康检查。

返回重点字段：

- `status`: 后端状态。
- `tags`: 当前启用变量数量。
- `channels`: 后端内部队列深度。
- `gateways`: MQTT运行状态。

### GET `/api/v1/gateways`

用途：查看 MQTT 运行状态，不返回密码。

返回示例：

```json
{
  "1": {
    "active": true,
    "client_id": "edge-local-kio",
    "broker": "tcp://127.0.0.1:1883",
    "main_topic": "datachange_S_KIO_Project",
    "write_result_topic": "setdata_result_S_KIO_Project_edge-test",
    "query_all_topic": "Query_AllKIOTags_S_KIO_Project",
    "subscribed_topics": [
      "datachange_S_KIO_Project",
      "setdata_result_S_KIO_Project_edge-test"
    ],
    "reconnects": 0,
    "last_connected": "2026-05-28T16:47:33.1814131+08:00",
    "last_full_sync": "2026-05-28T16:47:33.1846728+08:00"
  }
}
```

## 2. 站点/MQTT源配置

对应表：`sys_gateways`。

密码字段可以提交，但查询时不会返回：

- `password`
- `kio_write_password`

### GET `/api/v1/gateway-configs`

用途：查询所有站点/MQTT源配置，包括禁用项。

### GET `/api/v1/gateway-configs/:gateway_id`

用途：查询单个站点/MQTT源配置。

### POST `/api/v1/gateway-configs`

用途：新增站点/MQTT源。新增后如果 `enabled=true`，后端会立即启动 MQTT 连接。

请求示例：

```json
{
  "name": "local-kio",
  "broker": "tcp://127.0.0.1:1883",
  "client_id": "edge-local-kio",
  "username": "Admin",
  "password": "admin",
  "topic": "datachange_S_KIO_Project",
  "qos": 2,
  "parser_type": "kingiot_kio",
  "kio_client_id": "S_KIO_Project",
  "kio_writer": "edge-test",
  "kio_write_username": "sa",
  "kio_write_password": "C12E01F2A13FF5587E1E9E4AEDB8242D",
  "setdata_topic": "setdata_S_KIO_Project",
  "write_result_topic": "setdata_result_S_KIO_Project_edge-test",
  "query_all_topic": "Query_AllKIOTags_S_KIO_Project",
  "enabled": true
}
```

### PATCH `/api/v1/gateway-configs/:gateway_id`

用途：编辑站点/MQTT源。修改后后端会按新配置重启该 MQTT 连接；如果 `enabled=false`，会停止该连接。

请求体只传需要修改的字段。

### DELETE `/api/v1/gateway-configs/:gateway_id`

用途：删除站点/MQTT源配置，并停止对应运行连接。

当前不会级联删除已经发现的变量，前端需要单独处理变量归属。

## 3. 变量发现

### POST `/api/v1/gateway-configs/:gateway_id/discover`

用途：请求上位机推送全部变量。

当前 KingIO/KIO 内部会发布：

```text
Query_AllKIOTags_{client_id}
```

响应只表示 MQTT broker 接收了请求，不表示变量已经全部写入数据库。前端应在成功后延迟刷新变量列表。

返回示例：

```json
{
  "gateway_id": 1,
  "topic": "Query_AllKIOTags_S_KIO_Project",
  "broker_accepted": true
}
```

兼容接口：

```text
POST /api/v1/gateways/:gateway_id/kio/query-all
```

## 4. 变量管理

对应表：`sys_tags`。

### GET `/api/v1/variables`

用途：查询变量定义表。

支持查询参数：

- `gateway_id`: 按站点/MQTT源过滤。
- `enabled`: `true` 或 `false`。
- `discovered`: `true` 或 `false`。
- `keyword`: 模糊查询 `raw_name`、`var_name`、`display_name`、`source_path`。

示例：

```text
GET /api/v1/variables?gateway_id=1&enabled=true&keyword=台1
```

### PATCH `/api/v1/variables/:variable_id`

用途：编辑变量属性。

支持字段：

- `var_name`
- `display_name`
- `display_name_en`
- `display_name_ja`
- `data_type`
- `unit`
- `decimal_places`
- `scale_factor`
- `offset_val`
- `var_group`
- `enabled`

存储目标、表名、列名、周期、变化死区、首帧存储和启用状态不再通过变量接口编辑，改用 `/api/v1/storage-routes`。

请求示例：

```json
{
  "display_name": "台1主轴温度",
  "display_name_en": "Station 1 Spindle Temperature",
  "display_name_ja": "1番ステーション主軸温度",
  "unit": "℃",
  "decimal_places": 1,
  "store_trigger": "on_detection",
  "enabled": true
}
```

`store_mode` 和 `store_trigger` 含义不同：

- `store_mode`: 怎么存，保留原有模式，例如变化存、周期存、变化+周期都存。
- `store_trigger`: 什么时候允许存。
  - `always`: 按原有方式一直允许存储。
  - `on_detection`: 默认值，平时不存，收到检测/任务通知后才允许存储。

变量显示名属于业务数据多语言，不进入前端 i18n 资源文件：

- `display_name`: 中文/默认显示名。
- `display_name_en`: 英文显示名。
- `display_name_ja`: 日文显示名。

前端按当前语言选择对应字段；如果英文或日文字段为空，回退到 `display_name`。

### PATCH `/api/v1/variables/:variable_id/assignment`

用途：后续把变量绑定到虚拟设备/工程时使用。当前阶段前端可以先不做。

### DELETE `/api/v1/variables/:variable_id`

用途：删除误发现变量。

## 5. 设备/项目分组

当前后端尚未拆出独立 `sys_projects` 表；前端看到的“项目/设备分组”在本阶段由 `sys_projects` 虚拟设备组承载。设备是 UI 菜单、工位页、检测任务和变量筛选会直接展示的业务对象，因此后端返回三语显示名。

### GET `/api/v1/Projects`

返回字段新增：

- `display_name`: 中文/默认显示名。
- `display_name_en`: 英文显示名。
- `display_name_ja`: 日文显示名。

兼容字段：

- `name`: 历史默认名，后端继续返回；新前端展示应优先使用 `display_name*`。

前端 fallback 建议：

```text
当前语言 display_name_xx -> display_name -> name -> project_code
```

### POST `/api/v1/Projects`

请求支持字段：

```json
{
  "project_code": "AC-01",
  "site_no": "PLC01",
  "display_name": "1号精密空调",
  "display_name_en": "Precision AC 1",
  "display_name_ja": "精密空調1号機",
  "model_name": "A",
  "image_ref": "",
  "placeholder": false
}
```

兼容说明：

- `name` 仍可提交。
- `name` 和 `display_name` 至少传一个。
- 若只传 `display_name`，后端会同步写入 `name`，保持旧 UI 可用。
- 若只传 `name`，后端会同步写入 `display_name`。

### PATCH `/api/v1/Projects/:id`

用途：更新已有设备/项目分组的 UI 展示名和状态。

支持字段：

- `site_no`
- `name`
- `display_name`
- `display_name_en`
- `display_name_ja`
- `model_name`
- `image_ref`
- `enabled`
- `blocked`
- `placeholder`

请求体只传需要修改的字段。

## 6. 实时值查看

### GET `/api/v1/realtime/variables`

用途：查看当前内存实时值。

当前阶段用于验证变量能否读到，不代表采集存储已经开始。

## 7. 检测标准

检测标准是可复用配置；单次检测开始时会复制一份标准项快照到 `detection_run_standard_items`，避免历史检测报告被后续标准修改污染。

变量是否参与检测拆成两个字段：

- `check_enabled`: 是否参与合格/超限判定。
- `store_enabled`: 是否检测期间写入历史数据。

### GET `/api/v1/detection-standards`

支持查询参数：

- `project_id`
- `project_code`
- `mode`
- `enabled`
- `keyword`

### POST `/api/v1/detection-standards`

请求示例：

```json
{
  "standard_code": "STD-AC-DEFAULT",
  "display_name": "精密空调默认检测标准",
  "display_name_en": "Default Precision AC Standard",
  "display_name_ja": "精密空調標準検査基準",
  "project_id": 1,
  "project_code": "AC-01",
  "mode": "standard",
  "enabled": true,
  "items": [
    {
      "var_id": 1001,
      "var_name": "supply_air_temp",
      "display_name": "送风温度",
      "check_enabled": true,
      "store_enabled": true,
      "required": true,
      "limit_ll": 15,
      "limit_l": 18,
      "limit_h": 30,
      "limit_hh": 35,
      "unit": "C",
      "decimal_places": 1,
      "sort_order": 10
    }
  ]
}
```

### GET `/api/v1/detection-standards/:id`

返回标准主信息和 `items`。

### PATCH `/api/v1/detection-standards/:id`

更新标准主信息。

### PUT `/api/v1/detection-standards/:id/items`

整体替换标准项，并自动让标准 `version + 1`。

### DELETE `/api/v1/detection-standards/:id`

删除标准和配置项。已经开始的检测保留自己的快照，不受影响。

### POST `/api/v1/detection-runs`

新增可选字段：

```json
{
  "project_id": 1,
  "test_no": "TEST-001",
  "mode": "standard",
  "standard_id": 1
}
```

返回的检测任务会包含：

- `standard_id`
- `standard_code`
- `standard_version`
- `standard_items`
