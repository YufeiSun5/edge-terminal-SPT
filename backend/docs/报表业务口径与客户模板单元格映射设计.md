# 报表业务口径与客户模板单元格映射设计

最后更新：2026-06-18

维护责任：`backend-ai`

本文记录 EB-069 报表生成的后端契约。主服务器读取本机查询视角可见的边缘端业务镜像表，只读生成报表产物，不直接修改边缘端业务表。

## 1. 英文名词中文解释

| 名词 | 中文解释 |
| --- | --- |
| `ReportPackage` | 报表业务包。一次报表生成 job 的完整输入、指标、变量、上下限、参数和追溯信息。 |
| `ReportMetric` | 报表指标。当前包括检测全时段平均值、最小值、最大值、样本数，以及预留的两小时合格窗口指标。 |
| `ReportFact` | 报表事实数据。指从同步库检测任务、变量特征、报警和标准快照中整理出的可计算数据。 |
| `cell_mapping` | 客户模板单元格映射。描述某个 Excel sheet 的某个 cell 要填入哪个任务字段、参数、变量指标或上下限。 |
| `params_json` | 报表请求参数 JSON。边缘端在检测任务报表请求中冻结，主服务器生成报表时读取。 |
| `manifest` | 产物清单 JSON。保存完整报表包和 readiness 信息，便于追溯 Excel 单元格来源。 |

## 2. 当前数据来源

- `sys_detection_tasks`：任务身份、编号、项目、开始/结束时间、状态。
- `detection_run_report_requests`：一行代表一份报表请求，包含模板、变量范围、参数和扩展字段。
- `detection_run_standard_items`：检测运行快照的上下限、报警启用、回差、保持时间、质量策略，以及变量默认上下限快照。
- `detection_run_features`：按任务和变量聚合后的样本数、平均值、最小值、最大值、首末样本时间。
- `detection_run_summaries`：任务汇总、历史行数、报警计数和检测结果。
- `rt_history_data` 和项目宽表：用于 readiness 判断历史是否已经同步到主服务器。
- `detection_limit_alarms`：用于 readiness 和后续报警追溯。

## 3. ReportPackage 契约

主服务器每处理一条 `detection_run_report_requests` 生成一个 job artifact，也就是一份正式 Excel 文件。同一次检测可以有多条报表请求，例如综合、温度、湿度三份报表会生成三份 Excel，而不是强行放进同一个 workbook。

生成结果中写入：

- `manifest.json` 的 `report_package` 字段。
- Excel 的 `Report_Package` sheet，第一行是完整 JSON，后续是变量指标摘要。该 sheet 与 `Report_Run`、`Report_Request`、`Readiness_Checks`、`Features`、`Manifest_JSON` 等内部追溯页默认隐藏，不作为客户查看页。
- 客户模板 sheet 的指定单元格填充值。默认读取 `sys_report_templates.params_schema_json.cell_mapping`；如果本次 `params_json.cell_mapping` 存在，则以本次请求映射覆盖模板默认映射。

核心结构：

```json
{
  "kind": "main_server_report_package",
  "version": 1,
  "generated_at": "2026-06-05T15:16:00+08:00",
  "task": {
    "edge_instance_id": "edge-1",
    "task_id": 218,
    "test_no": "EB065-20260604144126",
    "project_id": 136,
    "project_code": "AC-01",
    "status": "stopped"
  },
  "reports": [
    {
      "request_id": 1,
      "report_name": "性能报表",
      "template_code": "PERF",
      "template_version": 1,
      "variables": [
        {
          "var_id_text": "9212397624135540856",
          "var_name": "temperature",
          "metrics": {
            "full_detection": {
              "status": "available",
              "sample_count": 120,
              "avg_value": 23.5
            },
            "qualified_two_hours": {
              "status": "insufficient"
            }
          },
          "limits": {
            "source": "detection_run_standard_items",
            "limit_l": 20,
            "limit_h": 30,
            "alarm_enabled": true
          }
        }
      ],
      "params": {}
    }
  ]
}
```

## 4. 上下限来源优先级

报表变量的 `limits` 按以下顺序装配：

1. `detection_run_standard_items.limit_ll/limit_l/limit_h/limit_hh`：检测业务运行快照，优先级最高。
2. `detection_run_standard_items.variable_default_limit_*`：变量默认上下限在检测开始时的快照，仅在业务上下限为空时兜底。
3. 无上下限时 `source=none`。

报表生成不读取边缘端当前变量属性来改写历史任务。已经结束的检测任务必须以同步过来的运行快照为准。

## 5. 时间窗指标

- `full_detection`：当前使用 `detection_run_features` 中已同步的检测全时段聚合值，包含 `avg/min/max/sample_count/first_sample_time/last_sample_time`。
- `qualified_two_hours`：主服务器 report worker 已基于同步历史做连续合格两小时窗口扫描。每个报表变量按 `var_id` 单独读取历史，优先使用项目宽表，宽表无数据时回退 `rt_history_data`，最多读取 10000 条样本。样本必须满足运行标准快照启用检测、质量策略允许、数值落在 `limit_ll/limit_l/limit_h/limit_hh` 内；遇到不合格样本会重置连续窗口。连续窗口跨度达到两小时后输出该窗口的 `avg/min/max/sample_count/first_sample_time/last_sample_time/status=available`；未达到时输出 `status=insufficient`。

## 6. Cell Mapping Schema

模板管理保存的 `sys_report_templates.params_schema_json` 可携带 `cell_mapping`，作为该模板的默认单元格映射。本次报表请求的 `params_json` 仍可携带 `cell_mapping`，用于覆盖模板默认映射：

正式模板映射只能用业务变量名 `var_name` 绑定变量来源，不使用 `var_id` 或 `var_id_text`。`var_id` 是某个项目/边缘内的具体点位快照，只能出现在任务启动后冻结的 `detection_run_report_requests.variables_json`、报表包和追溯页中。后端在检测启动或追加报表请求时用当前 `project_id + var_name` 解析目标项目自己的 enabled 变量并冻结真实 `var_id`；找不到或同一项目内存在多个 enabled 同名变量时直接失败。

前端显示变量时不应把 `var_name` 当用户主文本。用户主文本按当前语言显示 `display_name/display_name_en/display_name_ja`，缺失时再 fallback 到 `display_name` 或 `var_name`；提交给后端的绑定值仍是 `var_name`。

```json
{
  "inlet_area_m2": 1.25,
  "cell_mapping": {
    "version": 1,
    "sheet": "Customer",
    "items": [
      { "cell": "B2", "source": "task.test_no", "required": true },
      { "cell": "B3", "source": "param.inlet_area_m2", "required": true },
      { "cell": "B4", "source": "metric.avg", "var_name": "supply_air_temp", "required": true },
      { "cell": "B5", "source": "limit.limit_h", "var_name": "supply_air_temp", "required": true }
    ]
  }
}
```

支持的 `source` 首段：

- `task.*`：任务身份，例如 `task.test_no`、`task.project_code`、`task.started_at`、`task.ended_at`。时间字段以 RFC3339 字符串写入客户单元格，避免 Excel 日期格式差异影响追溯。
- `request.*`：报表请求，例如 `request.report_name`、`request.template_code`。
- `summary.*`：检测汇总，例如 `summary.result_status`、`summary.duration_ms`。
- `param.*` 或 `params.*`：报表参数，例如 `param.inlet_area_m2`。
- `variable.*`：变量信息，例如 `variable.var_name`、`variable.display_name`、`variable.unit`。
- `metric.*`：检测指标，例如 `metric.avg`、`metric.min_value`、`metric.max_value`、`metric.sample_count`、`metric.qualified_two_hours.status`。
- `limit.*`：上下限，例如 `limit.limit_l`、`limit.limit_h`、`limit.limit_deadband`。

当某项 `required=true` 且来源无法解析时，报表 job 失败并记录错误；非 required 缺失时填空。

## 7. 已实现和未完成

已实现：

- 主服务器 report worker 生成 `ReportPackage`。
- `manifest.json` 写入 `report_package`。
- Excel 写入隐藏的 `Report_Package` 留痕页，内部追溯 sheet 不进入历史页客户可见 tab。
- `sys_report_templates.params_schema_json.cell_mapping` 可按指定 sheet/cell 填任务编号、参数、变量指标和上下限；`params_json.cell_mapping` 可覆盖模板默认映射。
- `cell_mapping.items[]` 的变量绑定只认 `var_name`；缺失 `var_name` 的 `metric.*`、`limit.*`、`variable.*` 映射不会按“唯一变量”或第一个变量兜底。
- 连续合格两小时窗口扫描已基于同步历史实现。
- 检测结束后主服务器 report worker 可自动发现已停止且有报表请求但尚无 job 的任务并入队生成。
- Excel 产物已支持把曲线图片插入客户可见业务 sheet。后端基于同步历史数据生成 PNG，再按模板级或请求级 `cell_mapping.chart_sheet/chart_cell` 放置；未指定 `chart_sheet` 时使用 `cell_mapping.sheet`。`Report_Charts` 只作为历史兼容页名，不再作为新报表默认展示页。
- 报表 job 事件已接入主服务器报表通知：`main_report_notifications.payload` 会带 `task_id/request_id/test_no/project_id/project_code/report_name/template_code`，前端在 `main_server` 模式下把 `report.job` 合并到现有通知中心和顶栏未读数，点击跳转历史任务的 `Excel 报表` tab。
- 历史 Excel 预览的 Luckysheet adapter 已能读取 `.xlsx` 内嵌图片和 sheet anchor，转换为 Luckysheet `images` 对象；预览只加载 Excel 可见 sheet，过滤隐藏/veryHidden 内部追溯页，并按实际列宽、行高换算图片像素位置，避免图片脱离目标单元格。正式图片仍以后端 Excel artifact 内的 PNG/drawing 为准。
- 历史页已支持“修改参数后重新生成”：主服务器创建新的 `main_report_jobs` generation，使用 `params_override_json` 覆盖本次生成参数，不回写边缘同步表中的 `detection_run_report_requests.params_json`，旧 artifact 保留。
- 主服务器 report worker 已落地系统默认报表模板，默认标识为 `template_code=SPINDLE_DEFAULT_REPORT`、`version=1`、`file_ref=templates/default-report-template.xlsx`。`EnsureSchema`/启动检查会确保默认模板文件和 `sys_report_templates` 记录存在；该模板只能作为请求显式选择的系统模板，缺少请求模板或模板文件不可达时 job 失败，不再静默兜底。
- 单报表请求、两个数值变量、参数、上下限、cell mapping、两小时合格窗口正向和超限重置负向已有单元测试覆盖。
- 多报表同任务测试已覆盖同一任务下多条 `detection_run_report_requests` 独立生成 job、xlsx artifact、manifest、隐藏 `Report_Package`、变量集合、指标、上下限和 `cell_mapping` 可见单元格；真实链路已覆盖综合、温度、湿度三份 Excel。
- 负向/边界测试已覆盖错误 edge 入队拒绝、缺 history/缺 feature 保持 `waiting_for_sync`、两小时窗口不足 `status=insufficient`、缺请求模板失败、单份 required `cell_mapping` 缺失只失败该 report。
- 等价客户 Excel 模板验收测试已覆盖真实 xlsx 模板文件路径：客户可见 sheet 的任务编号、项目、边缘、开始/结束时间、全检测平均值、两小时合格窗口均值与状态、上下限、判定参数和单位均由模板级或请求级 `cell_mapping` 写入，并与 `Report_Package` 和 manifest `report_package` 追溯来源一致。
- 默认模板 seed 测试已覆盖 `sys_report_templates` 元数据、默认 xlsx 文件和默认 sheet 内容；显式选择 `SPINDLE_DEFAULT_REPORT v1` 的报表会在 `Report_Run.template_source` 记录 `templates/default-report-template.xlsx`。缺请求模板或模板文件不可达不生成客户报表。
