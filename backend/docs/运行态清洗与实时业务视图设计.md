# 运行态清洗与实时业务视图设计

## 目标

本文固定数据到达后的上行链路、变量下设的下行链路、内存 map 分层，以及后续报警、运行中配置生效和规则触发器的站位边界。

本轮后端实施只做到实时底座：高速清洗滤网、`gateway/topic -> tags` 热路径索引、全局变量实时 map、按项目/设备的实时视图，以及稳定值到 WebSocket 和历史存储的基础分流。

实施状态：EB-033 首段已完成 `gateway/topic -> tags` 索引、`project_id -> tags` 项目/设备实时视图、数值清洗滤网和稳定值存储/WS 基础分流；自动发现变量默认只作为未绑定候选入库，只有 `enabled=true` 且已绑定 `project_id` 的变量才会进入运行态清洗；报警状态机、运行中配置即时生效、KIO/WS 下设完整闭环和多变量组合触发器仍为后续站位。

当前“项目/设备”在后端统一建模为 `sys_projects.project_id`：

- map key 使用 `project_id`。
- 稳定编码使用 `project_code`。
- 前端显示名使用 `display_name`、`display_name_en`、`display_name_ja`，并 fallback 到 `name`、`project_code`。
- `site_no` 只作为站点/项目编号或辅助分组，不作为实时 map key。

## 运行态变量资格

发现变量和运行态变量不是同一件事。

- 自动发现只登记来源候选：`discovered=true`、`enabled=false`、`project_id=null`。
- 变量分配到项目/设备并启用后，才成为运行态变量：`enabled=true` 且 `project_id IS NOT NULL`。
- `Repository.LoadTags()`、`TagManager.Load()` 和 `TagManager.Upsert()` 都执行同一资格判断，防止未知变量绕过任一入口进入清洗。
- 未绑定候选变量可以在变量管理页面展示、搜索、分配和补属性，但不参与清洗、WS 快照、历史存储、检测判定或变量写命令。
- 虚变量也需要绑定项目/设备才进入运行态；未绑定虚变量只是配置记录。

## 上行链路

```text
MQTT/KIO payload
  -> gateway/topic 索引匹配 tags
  -> parse/extract
  -> type convert
  -> scale_factor/offset_val
  -> quality normalize
  -> suspicious/debounce/deadband/startup filter
  -> GlobalTagMap
  -> ProjectRealtimeView / ProjectRunContext
  -> WS / history store queue / later detection evaluator
```

清洗层是一层高速滤网，只处理变量事实：

- 类型转换。
- 系数和偏移。
- 质量码归一。
- 可疑值。
- 防抖 pending。
- 运行态死区。
- 首帧策略。

清洗层只处理运行态变量，不清洗所有发现到的未知来源。这样可以把变量发现作为低频配置入口，把实时清洗保持为项目/设备业务变量的高速路径。

清洗层禁止做这些事：

- 查数据库。
- 计算上下限。
- 计算 OK/NG。
- 写 MySQL。
- 触发复杂业务规则。
- 替换整份变量配置。

防抖 pending 值不进入 WebSocket、不入历史、不参与检测。定时存储遇到 pending 时直接使用最后稳定值，不等待防抖结束。

## 内存 Map 分层

### GlobalTagMap

`GlobalTagMap` 保存唯一变量事实。

```text
var_id -> *Tag
```

只有通过运行态资格判断的变量会进入 `GlobalTagMap`。

`Tag` 只保存：

- 变量配置快照：来源、展示、存储映射、读写约束。
- 运行态：current/last value、quality、last_update、last_change、debounce pending。

`Tag` 不保存：

- 上下限。
- 检测 OK/NG。
- 当前报警状态。
- 当前任务规则。

同一个变量被多个项目/设备引用时，只共享同一个 `Tag`，不复制清洗状态。

### GatewayTopicIndex

为了避免每条 MQTT 消息全量扫描所有变量，`TagManager` 需要增加 topic 级索引：

```text
gateway_id + topic -> []*Tag
```

热路径入口应从 `tags.All()` 改为：

```text
tags.ForMessage(gateway_id, topic)
```

如果索引缺失，允许 fallback 到 `All()`，保证兼容旧数据和异常配置。`source_path` 级倒排索引后续再做，不放在本轮。

### ProjectRealtimeView

`ProjectRealtimeView` 负责项目/设备页面和 WS 变量视图装配。

```text
project_id -> []var_id
```

这一层不保存上下限，不保存报警状态。它只表示“这个项目/设备页面应该看哪些变量”。

### ProjectRunContext

`ProjectRunContext` 负责当前运行任务上下文。

```text
project_id -> ActiveRunContext
ActiveRunContext.items[var_id] -> RunItemRule
```

本轮只需要读取当前任务的存储和检测基础规则：

- `store_enabled`
- `check_enabled`
- 变量存储映射快照

后续检测事件阶段再扩展完整状态：

- 上下限。
- 回差。
- 超限保持时间。
- 恢复保持时间。
- 质量策略。
- 当前 OK/NG。
- 当前报警状态。

## 存储分流

历史存储只读稳定值。

变化存储：

```text
accepted stable value
  -> changed && store_deadband satisfied
  -> active task exists
  -> run item store_enabled=true
  -> enqueue StoreTask
```

定时存储：

```text
cycle tick
  -> read last stable value
  -> active task exists
  -> run item store_enabled=true
  -> enqueue StoreTask
```

规则：

- pending 值不入库。
- 无 running task 且 `store_trigger=on_detection` 时不入库。
- `store_enabled=false` 时不入库。
- MySQL 写入继续走 store queue，不能阻塞采集热路径。

## WebSocket 分流

本轮保留现有 1 秒 snapshot 机制：

- `realtime.variables.snapshot` 来自 `GlobalTagMap + ProjectRealtimeView`，只推清洗后的稳定值。
- `detection.runs.snapshot` 继续来自当前 active task。
- `notification.event` 来自运行态 `Notify` 总线，推送超限报警进入/恢复/等级变化、检测开始/停止/暂停/恢复和检测结果 OK/NG；它只做即时提示，历史追溯仍看 `detection_limit_alarms`、`detection_run_events` 和 `detection_run_summaries`。
- 后续 `detection.status.snapshot/delta` 从 `ProjectRunContext` 输出。

WS 不应推送：

- raw value。
- debounce pending value。
- 未绑定业务设备且订阅无权限访问的候选变量。

## 变量下设链路

物理变量下设和实时值更新是两条状态。

```text
HTTP/WS command
  -> auth
  -> command_id idempotency
  -> audit accepted/rejected
  -> validate writable/rw_mode/write_path/type/range/enum
  -> SourceAdapter/KIO service
  -> adapter ack/timeout
  -> audit success/failed/timeout
  -> command result
  -> wait upstream readback
  -> clean/filter
  -> update GlobalTagMap
  -> WS realtime snapshot/delta
```

规则：

- 前端只传 `var_id + value`，不能传 MQTT topic 作为最终写目标。
- 物理变量写成功不直接改 `GlobalTagMap`，必须等上行读回。
- 虚变量没有外部读回，可由后端 service 直接更新 `GlobalTagMap`，但仍必须校验和审计。
- 检测开始/停止是业务命令，走 `DetectionRunsService`；如需联动写标志位，后续作为可配置动作单独设计和审计。

- 物理变量实时值仍以上行读回为准。

## 性能风险与约束

当前最大热点是每条 MQTT 消息遍历所有 tag。topic 级索引必须先设计并落地，避免变量量增加后清洗层被全量扫描拖住。

约束：

- 高频采集路径只读内存。
- 配置更新是低频路径，可以重建索引和内存视图。
- WS snapshot 不能持有大锁做长时间复制。
- Store queue 满时允许丢弃并记录日志，不能阻塞 MQTT logic worker。

## 测试计划

Topic 索引：

- `ForMessage(gateway_id, topic)` 只返回该网关/topic 下变量。
- 同一 topic 多变量都能处理。
- reload/upsert 后索引同步更新。
- 索引未命中 fallback 到全量变量。

清洗：

- scale/offset 后进入稳定值。
- suspicious 值不覆盖稳定值。
- debounce 未满足时 pending，不推送、不入库。
- debounce 满足后 accepted。
- deadband 内小波动不更新稳定值。
- string/bool 路径不被破坏。

存储和 WS：

- pending 值不入 Store 队列。
- 定时存储使用最后稳定值。
- `store_enabled=false` 阻止入库。
- WS snapshot 读取清洗后的稳定值。
- 订阅过滤和断线重连保持通过。

后续能力：
