# 报表端到端用户路径测试计划

最后更新：2026-06-18

维护责任：`test-ai`

本文用于指导报表链路验收测试。测试按用户真实使用方式组织，不按前后端模块拆散。当前边界默认主服务器库和边缘库内容最终一致，只允许短时时差；应用层不测试同步软件上线，不把同步软件作为阻塞项，也不依赖数据库外键。

## 1. 测试目标

验证一名主服务器用户和一名现场工位用户可以完成以下闭环：

```text
主服务器上传报表模板
-> 主服务器导入计划 Excel
-> 后端解析检测任务、检测规则、上下限、报表请求和任务参数
-> 用户确认后创建检测配置和待检测计划
-> 现场工位选择待检测计划并开工
-> 开工通过 watched STRING 虚拟变量触发任务流
-> 边缘创建真实检测任务并冻结检测配置、参数、报表请求和存储路由
-> 检测满足合格持续时间后结束
-> 主服务器自动生成多份 Excel 报表
-> 历史页查看报表、切换 generation、修改参数重新生成
-> 数据下载页打包下载 zip
```

测试通过后，才能说报表主链路具备现场试运行基础。

## 2. 测试角色和入口

主服务器用户：

- 使用 `http://127.0.0.1:5273/`。
- 负责模板管理、导入计划、查看历史报表、重新生成、下载包。
- 所有 API 走主服务器 `19080`，浏览器不得直连边缘 `18080`。

现场工位用户：

- 使用主服务器工位页或边缘工位页，具体按当前部署入口。
- 负责选择待检测计划并开始检测。
- 正式开工路径必须是 `command.write_variable` 写 watched STRING 变量，触发任务流里的 `builtin.start_detection_run`。

## 3. 测试数据

项目范围：

- 只使用 `AC-01` 到 `AC-08`。
- 第一轮建议用 `AC-01` 做主路径。
- 第二轮必须用 `AC-02` 验证项目组标准跨设备复用。
- 不使用 `AC-09+`，不使用冒烟项目作为现场通过证据。

变量：

- 温度变量：使用当前项目里同名温度变量，优先选择“再热器出口温度”或现场已有温度变量。
- 湿度变量：使用当前项目里同名湿度变量。
- AC-01 和 AC-02 必须存在同名变量；如果不存在，测试停止，先补变量映射或项目数据。

模板：

- 综合报表模板：一份 Excel，1 个业务 sheet，包含温度和湿度。
- 温度报表模板：一份 Excel，1 个业务 sheet，只写温度。
- 湿度报表模板：一份 Excel，1 个业务 sheet，只写湿度。
- 每份 Excel 第一版只要求 1-2 个可见业务 sheet；内部追溯 sheet 可隐藏。
- 模板必须包含：
  - 出厂编号；
  - 客户；
  - 机型；
  - 检测编号；
  - 上下限；
  - 任务参数；
  - 合格时间段平均值；
  - 后端写入的计算结果；
  - 曲线图片落点。

任务参数：

- `temp_coefficient=1.10`
- `humidity_coefficient=0.95`
- `end_policy=qualified_hold`
- 第一轮为了缩短验收可用 `qualified_hold_minutes=10`。
- 最终接近真实验收再跑 `qualified_hold_minutes=40`。

上下限：

- 先使用宽松上下限，保证检测合格，例如 `0~100`。
- 计划导入解析必须覆盖至少一条 `10~20%` 或 `10±5` 样例，验证解析能力。

## 4. 主路径测试

### T1 模板管理

用户动作：

1. 进入“报表设置 / 模板管理”。
2. 上传综合、温度、湿度三份 `.xlsx` 模板。
3. 为每份模板保存 mapping JSON。
4. 下载模板副本。
5. 打开模板预览。

必须验证：

- 模板列表出现 3 条模板。
- 模板编码、名称、版本、启用状态正确。
- 后端保存的是模板副本 artifact，不是浏览器临时文件。
- 下载副本能用 Excel 打开。
- Luckysheet 预览能看到业务 sheet，样式基本一致。
- 模板 mapping 保存后刷新页面仍存在。

失败即停止：

- 上传后没有后端 artifact。
- 页面只保存 Luckysheet JSON，没有保存原始 xlsx 副本。
- 模板缺 mapping 却能继续宣称通过。

### T2 导入计划

用户动作：

1. 进入“报表设置 / 导入计划”。
2. 上传计划 Excel。
3. 查看解析草稿。
4. 人工确认低置信度或一侧上下限。
5. 点击确认导入。

必须验证：

- 计划 Excel 中的出厂编号、客户、机型、检测项、检测顺序被解析。
- 上下限文本保留原文、单位、解析模式、置信度。
- `10~20%`、`10±5`、`10±5%`、`>=10`、`<=20` 至少覆盖三类。
- 变量能按当前项目匹配。
- 报表模板能按模板编码匹配。
- 创建出的检测配置写入 `sys_detection_standards` 和 `sys_detection_standard_items`。
- 检测标准 `project_group` 正确。
- 创建出的待检测计划写入 `sys_detection_plans(status=pending)`。
- 计划的 `report_request_json` 包含三份报表请求：综合、温度、湿度。
- 计划参数包含 `temp_coefficient`、`humidity_coefficient`、`end_policy`、`qualified_hold_minutes`。

失败即停止：

- 导入确认后只创建检测配置，没有创建 `sys_detection_plans`。
- `report_request_json` 为空。
- 报表请求没有变量。
- 检测配置 hash/version/updated_at 没按规范写。

### T3 工位从待检测计划开工

用户动作：

1. 打开工位页面。
2. 点击开始检测。
3. 选择刚导入的待检测计划。
4. 检查带出的出厂编号、客户、机型、检测项、检测配置、报表请求。
5. 点击开始。

必须验证：

- 前端找到当前项目的 watched STRING 启动任务流，不硬编码 `task_request`。
- 开工请求最终走 `command.write_variable`。
- 边缘 `VariableWriteService` 写入 watched STRING 变量。
- `task_flow_runs` 中出现 data_change 触发记录。
- 任务流执行 `builtin.start_detection_run`。
- 创建真实 `sys_detection_tasks`。
- `sys_detection_plans.status` 从 `pending` 变为 `started`。
- `started_task_id` 回写。
- 真实任务冻结：
  - 检测配置；
  - 标准项；
  - 存储路由；
  - `process_params`；
  - `report_request`；
  - `qualified_hold_ms`。

失败即停止：

- 前端或主服务器直接调用 legacy `/api/v1/detection-runs` 当正式开工。
- 计划开工失败后仍创建了真实任务。
- `detection_run_report_requests` 为空。
- 存储路由没有冻结。

### T4 合格结束和历史数据

用户动作：

1. 等待任务运行到合格持续时间。
2. 打开“历史与计划 / 历史”。
3. 进入该任务详情。
4. 查看详细数据、报警与事件。

必须验证：

- 任务自动停止，`end_type=qualified_hold`。
- `result_status=ok`。
- 温度、湿度均有历史数据。
- `detection_run_features` 有温度、湿度统计。
- 无超限报警，或报警符合设定。
- 历史详情不是跳到其他最新任务。

失败即停止：

- 任务一直运行，不触发合格结束。
- 历史无数据。
- features 为空。
- 页面展示的 task id 与 URL 不一致。

### T5 自动报表生成

用户动作：

1. 停止后等待主服务器 report worker 自动生成。
2. 打开历史详情“Excel 报表”。

必须验证：

- 对同一任务生成 3 个 report job。
- job 状态为 `succeeded`。
- 每个 job 有 `.xlsx` artifact。
- 通知中心出现报表开始/成功通知。
- 历史 Excel 报表左侧显示 3 份报表名称。
- 右侧 Luckysheet 加载实际生成的 Excel artifact。
- 可见 sheet 是业务 sheet，不展示隐藏追溯 sheet。
- 曲线图片位置与 Excel 导出位置一致。

失败即停止：

- worker 不自动生成且没有明确原因。
- 只能手动 force enqueue 才生成。
- Luckysheet 预览空白。
- 导出的 Excel 和预览内容明显不一致。

### T6 修改参数重新生成

用户动作：

1. 在历史 Excel 报表页选择综合报表。
2. 点击“修改参数重新生成”。
3. 修改 `temp_coefficient` 或 `humidity_coefficient`。
4. 提交。
5. 切换 generation 查看旧版和新版。

必须验证：

- 新建 `main_report_jobs` 行。
- 新 job 有 `parent_job_id`。
- `generation_type=params_override`。
- 原始 `detection_run_report_requests.params_json` 不被覆盖。
- 旧 artifact 仍可查看。
- 新 artifact 中参数和计算结果变化。
- 右侧 generation 下拉可以切回旧版。

失败即停止：

- 重新生成覆盖旧文件。
- 重新生成回写原始 report request。
- 前端只能看最新版本，无法追溯旧版本。

### T7 数据下载

用户动作：

1. 打开历史详情“数据下载”。
2. 勾选部分项：一份报表、历史数据、配置快照、事件。
3. 点击“下载所选”。
4. 再点击“下载全部”。

必须验证：

- 前端调用 `POST /api/v1/main-server/download-packages`。
- 浏览器不使用 JSZip 自己拼包。
- zip 包含：
  - `download-manifest.json`；
  - `snapshots/task.json`；
  - `snapshots/standard-items.json`；
  - `snapshots/limit-snapshot.json`；
  - `snapshots/storage-routes.json`；
  - `snapshots/report-requests.json`；
  - `events/task-events.json`；
  - `events/alarm-records.json`；
  - `data/history-raw.csv`；
  - 选中的正式报表 `.xlsx`；
  - `reports/report-job-*-events.json`。
- 请求曲线图片但没有独立 PNG artifact 时，`download-manifest.json.skipped` 有明确原因。
- Excel 文件可打开。

失败即停止：

- zip 是前端临时构造的。
- 报表 Excel 不是 report job artifact。
- 缺 artifact 时仍生成半真包。

## 5. 跨项目组标准测试

目的：验证“检测标准不按单台设备私有，而是可按项目组通用”。

用户动作：

1. 在 AC-01 或主服务器创建 `project_group=AC` 的检测标准。
2. 确认 AC-02 也属于 `project_group=AC`。
3. 在 AC-02 工位开始检测弹窗选择该项目组标准。
4. 开工并生成一个短任务。

必须验证：

- AC-02 能看到项目组标准。
- 标准作用域显示为“项目组 AC”。
- 启动时按 `var_name` 把标准项重映射到 AC-02 自己的变量。
- `detection_run_standard_items.var_id` 属于 AC-02。
- `detection_run_storage_routes.var_id` 属于 AC-02。
- 不冻结 AC-01 的变量。

失败即停止：

- AC-02 看不到项目组标准。
- AC-02 启动后冻结 AC-01 的 var_id。
- 后端仍按 `project_id` 精确匹配阻止项目组标准。

## 6. 负向测试

导入负向：

- 模板编码不存在：不能确认导入。
- 变量不存在：不能确认导入。
- `10±5` 解析低置信度且未确认：不能确认导入。
- 上限小于下限：不能创建检测配置。
- 同一检测配置内重复变量：必须拒绝。

开工负向：

- 项目没有 watched STRING 启动任务流：前端提示配置启动任务流。
- 启动变量不存在：计划回到 `pending`，写 `error_message`。
- 任务流未命中：计划回到 `pending`，不创建真实任务。
- 当前项目已有运行任务：拒绝开工。

报表负向：

- 模板 artifact 缺失：job failed，不使用默认模板兜底。
- required mapping 缺值：该报表 failed。
- 报表请求为空：历史页显示无报表请求，不生成空报表。
- artifact 未成功时下载包请求报表：返回 `report_artifact_not_ready`。
