# 边缘项目归属与工位显示边界草案

状态：想法阶段，未实现。本文记录当前讨论方向、现状偏差、建议边界和后续测试条件，不代表代码已经满足。

日期：2026-06-24

## 背景

目标部署模型中，历史数据是单向同步：边缘只保留自己的历史，主服务器拥有全部历史副本。除历史数据外，配置类数据计划由同步软件做全双向同步，并由主服务器承担仲裁：边缘变更先同步到主，主裁决后的变更再随同步或消息分发到其他边缘。

在这个模型下，变量表、项目表、网关表、任务流、工位显示配置等配置表可能在每个边缘库中都出现全量数据。边缘应用不能因为本地数据库里有全量配置，就把其他边缘的项目页面、变量、网关或任务流加载进本机运行态。

边缘本机应由启动配置决定身份，当前已有配置字段是 `auth.edge_instance_id`。这个身份应作为边缘后端过滤项目、变量、网关和运行配置的根上下文。前端不应靠 URL 或本地隐藏逻辑决定边缘身份。

## 当前现状

已有链路：

- 边缘启动时使用 `auth.edge_instance_id`。
- 运行态 `LoadTags(edgeInstanceID)` 已按项目归属加载变量。
- 运行态 `LoadGateways(edgeInstanceID)` 已按网关归属加载 MQTT 网关。
- 运行态 `LoadActiveDetectionTasksForEdge(edgeInstanceID)` 已按边缘恢复活动检测。
- 运行态 `LoadEnabledTaskFlowsForEdge(edgeInstanceID)` 已按项目归属加载任务流。
- 工位 effective view 已接收本边缘 ID，并会拒绝明显不属于本边缘的项目。
- 主服务器查询层已有按 `edge_instance_id` 聚合和过滤的模型，适合承担“看全部、按边缘过滤、桥接控制”的角色。

主要偏差：

- 边缘 `/api/v1/projects` 当前按 `enabled=true` 返回项目，没有按本边缘 ID 过滤。左侧工位列表由这个接口动态生成，因此全同步后可能显示其他边缘项目。
- 网关配置列表、任务流配置列表、存储路由管理入口仍存在全表读取或缺少项目归属校验的风险。
- 空字符串或 NULL 的 `edge_instance_id` 当前作为 legacy 兼容会被多个边缘视为可见。如果生产配置表全双向同步，真实项目和真实网关长期空归属会导致跨边缘可见。
- 前端部分 API 支持传 `edge_instance_id` 查询参数，但边缘 Electron 模式不应依赖用户传参。边缘身份应由边缘后端启动配置决定；主服务器模式才需要显式 edge 上下文。

## 目标边界

边缘端：

- 边缘后端是本机可见范围的事实源。
- 边缘前端只消费本机后端返回的项目、变量和工位视图，不自行拼接跨边缘过滤规则。
- 一个边缘可以挂一个项目，也可以挂多个项目。
- 左侧工位列表来自本边缘 `/api/v1/projects` 返回的项目。
- 工位页面以 `project_id` 为页面身份：先取该项目的 effective view，再按返回的 binding 和 `ws_subscription.var_ids` 订阅实时值。
- 检测运行中只显示本次检测冻结快照，不使用检测前 runtime draft 或其他草稿状态。

主服务器：

- 主服务器可以看全部项目和全部边缘。
- 主服务器显示应按 `edge_instance_id -> projects` 分组。
- 主服务器调用实时、控制或 runtime draft 时必须明确目标边缘，或能由 `project_id` 唯一解析目标边缘。
- 主服务器不把实时值、控制状态或边缘内存状态伪造成同步库字段。

## 建议归属模型

1. `auth.edge_instance_id` 是边缘进程身份。
2. `sys_projects.edge_instance_id` 是真实检测项目归属。
3. `sys_gateways.edge_instance_id` 是真实采集网关归属。
4. 已绑定项目的变量，归属跟 `sys_tags.project_id -> sys_projects.edge_instance_id` 走。
5. 未绑定项目的物理变量，归属跟 `sys_tags.gateway_id -> sys_gateways.edge_instance_id` 走。
6. `gateway_id=0` 或未绑定项目的虚拟变量只能作为候选池，不能直接进入工位页面；要显示、检测或存储，必须绑定到本边缘项目或被本边缘项目的配置显式引用。
7. 真实项目和真实网关不应长期使用空 `edge_instance_id`。空值只作为迁移期 legacy 兼容。

## 工位显示模型

边缘端显示流程：

```text
边缘启动
  -> 读取 auth.edge_instance_id
  -> GET /api/v1/projects
  -> 后端只返回本边缘项目
  -> 左侧工位列表动态生成

用户打开某项目工位
  -> GET /api/v1/station-view/effective?project_id=<local_project_id>
  -> 后端校验项目归属
  -> 返回 template、items、resolved_bindings、ws_subscription.var_ids
  -> 前端生成左侧卡片和右侧表格
  -> WS 只订阅该 project_id + var_ids
```

一个边缘只有一个项目时，前端可以自动进入唯一项目；一个边缘有多个项目时，左侧展开多个项目。URL 中如果传入非本边缘项目，前端应清理或回退到第一个本边缘项目，后端同时应拒绝该项目的 effective view、realtime、runtime draft 和控制请求。

主服务器显示流程：

```text
主服务器项目列表
  -> 读取全部启用项目
  -> 按 edge_instance_id 分组
  -> 展示 edge-ac-01 / edge-ac-02 / ...

主服务器打开某项目
  -> project_id + edge_instance_id 唯一确定目标边缘
  -> 静态配置可查同步库
  -> 实时/控制/runtime draft 通过 service-token 桥接到对应边缘
```

## 建议改动范围

改动集中点不在采集核心，也不在工位页面大重构，而是在边缘后端 API 的可见范围边界，以及主服务器的多边缘路由语义。

边缘端集中改动：

- 项目入口：`/api/v1/projects` 是左侧工位、驾驶舱、通知筛选和开始检测项目选择的共同入口，必须按本机 `auth.edge_instance_id` 返回本边缘项目。
- 配置管理入口：`/gateway-configs`、`/task-flows`、`/storage-routes` 以及其他带 `project_id/gateway_id/var_id/flow_id` 的边缘配置接口，需要统一列表、详情、创建、修改、删除的归属校验。
- 归属校验 helper：应集中判断项目是否属于本边缘、网关是否属于本边缘、变量是否属于本边缘项目或本边缘网关，避免每个 handler 手写一套条件。
- 前端显示兜底：只补无项目空态、单项目自动进入、多项目展开、URL 传入外边缘 `project_id` 时回退等体验，不承担安全过滤。

主服务器集中改动：

- 聚合显示：主服务器不能像边缘一样只看本机，应按 `edge_instance_id -> projects` 分组展示全部项目。
- 路由解析：实时、控制、runtime draft 和 WS 命令必须能由 `project_id + edge_instance_id` 唯一确定目标边缘；解析不唯一或不匹配时硬失败。
- 静态配置与运行态分离：主服务器可以读同步库配置和历史，但实时值、控制命令、边缘内存 draft、运行诊断必须走 service-token 到目标边缘。
- 仲裁后的分发语义：主服务器改配置后，数据库同步只负责持久配置分发；在线边缘是否需要 reload/control 消息，需要明确成独立运行态同步策略。

边缘端面临的问题：

- 本地库未来会有全量配置，边缘 API 如果继续全表读，会显示或修改其他边缘项目。
- 空 `edge_instance_id` 的 legacy 兜底在生产全同步后会让真实项目和真实网关变成“所有边缘可见”。
- 运行态过滤和配置页过滤不一致：运行时可能只加载本边缘，但管理页面仍可能看到其他边缘配置。
- 工位动态页面依赖项目列表，如果项目列表污染，后续 station-view、runtime draft、realtime 订阅和控制入口都会被外边缘项目牵连。

主服务器面临的问题：

- 主服务器看全量数据，必须防止无 edge 上下文的控制命令。
- `project_id + edge_instance_id` mismatch 必须硬失败，不能猜测或自动改路由。
- 目标边缘离线时，不能缓存 runtime draft 或控制请求，必须返回离线或转发失败。
- 一套前端同时服务边缘和主服务器时，显示模型不同：边缘是本机项目列表，主服务器是多边缘分组列表，这个差异需要由 API/role 清楚吸收。

第一阶段，收敛页面入口：

- 边缘 `ProjectsHandler` 持有 `cfg.Auth.EdgeInstanceID`。
- 边缘 `/api/v1/projects` 默认只返回本边缘项目，迁移期可选择包含 legacy 空归属项目。
- 边缘创建项目时，如果 payload 未传 `edge_instance_id`，默认写当前边缘 ID。
- 边缘修改项目时，禁止把项目显式改到其他边缘。
- 前端在无 `project_id` 且只有一个本地项目时自动进入；多项目时保持列表；无项目时显示空态。

第二阶段，收敛配置入口：

- `/gateway-configs` 只展示和修改本边缘网关，创建时默认写当前边缘 ID。
- `/task-flows` 列表、详情、手动运行、创建、修改和删除都校验项目归属。
- `/storage-routes` 列表、创建、修改和删除都校验项目归属和变量归属。
- 其他以 `project_id`、`gateway_id`、`flow_id`、`var_id` 作为入口的边缘 API 统一复用同一个归属校验 helper。

第三阶段，收敛数据治理：

- 补齐生产项目 `sys_projects.edge_instance_id`。
- 补齐生产网关 `sys_gateways.edge_instance_id`。
- 明确哪些配置允许全局共享，例如项目组检测标准、报表模板、全局 station-view 模板。
- 引入可选严格模式，例如 `sync.strict_edge_scope=true`。严格模式下边缘不再加载空归属的真实项目和真实网关。

## 未决问题

- 迁移期是否允许 `/projects` 返回空 `edge_instance_id` 的 legacy 项目，还是只在管理页提示“待归属”。
- 严格模式何时启用，以及启用前需要哪些数据修复脚本。
- 主服务器仲裁后是只依赖数据库同步，还是对在线边缘同时发运行态 reload/control 消息。
- 全局共享配置的清单需要收敛：检测标准、报表模板、station-view 模板、任务流模板是否都允许跨边缘共享，哪些必须项目归属。
- 非本边缘项目请求的错误语义统一为 `404 not_found` 还是 `409 edge_instance_mismatch`。

## 测试条件

测试前置数据：

- 至少准备两个边缘身份，例如 `edge-ac-01` 和 `edge-ac-02`。
- 每个边缘至少一个真实项目；其中一个边缘准备两个项目，用于验证多工位列表。
- 准备一批全同步变量：本边缘项目变量、其他边缘项目变量、本边缘网关未分配变量、其他边缘网关未分配变量、`gateway_id=0` 虚拟候选变量。
- 准备本边缘和其他边缘的网关配置、任务流、存储路由。
- 准备少量空 `edge_instance_id` legacy 项目和网关，用于验证迁移期行为。
- 如果使用真实现场编号，仍只使用 `AC-01..AC-08`，不使用 `AC-09+` 或临时 smoke 项目作为通过证据。

边缘后端单元测试：

- `ListProjectsForEdge(edge-ac-01)` 只返回 `edge-ac-01` 项目；迁移期策略允许时才返回 legacy 项目。
- `GetProjectForEdge(edge-ac-01, edge-ac-02 project)` 返回不匹配错误或 not found。
- 创建项目未传 `edge_instance_id` 时写入当前边缘 ID。
- 修改项目时不能显式改到其他边缘。
- 变量列表只返回本边缘项目变量和本边缘网关候选变量。
- 网关配置、任务流、存储路由列表和详情都拒绝其他边缘对象。

边缘集成测试：

- 使用同一个本地库中存在两台边缘的全量配置数据启动 `edge-ac-01` 后端。
- `GET /api/v1/projects` 只返回 `edge-ac-01` 项目。
- 左侧工位列表只显示 `edge-ac-01` 项目；`edge-ac-01` 有两个项目时显示两个子项。
- 打开本边缘项目时，`station-view/effective` 返回绑定和 `ws_subscription.var_ids`。
- 打开其他边缘项目时，`station-view/effective`、`runtime-drafts`、`realtime/variables`、检测启动或控制请求都失败，不静默返回其他边缘数据。
- WebSocket 订阅只包含当前项目的 `project_id` 和 effective view 返回的 `var_ids`，切项目后不会继续显示上一个项目变量。
- 无项目边缘显示明确空态，不请求全量实时变量。

主服务器集成测试：

- 主服务器项目列表能按 `edge_instance_id` 分组展示所有项目。
- 主服务器打开 `edge-ac-01 + AC-01` 时，浏览器 HTTP/WS 只访问主服务器，不直连边缘端口。
- 主服务器 `project_id + edge_instance_id` 不匹配时返回明确错误。
- 目标边缘离线时，实时、控制和 runtime draft 返回离线或转发失败，不写中心缓存。
- 主服务器静态配置查询可以看全量同步库，但实时和控制必须走目标边缘。

同步仲裁测试：

- 在边缘 A 修改一个本边缘项目配置，同步到主服务器后，主服务器裁决结果再同步到边缘 B。
- 边缘 B 本地库能看到该配置行，但边缘 B 的 `/projects`、工位页面、实时订阅和控制入口都不加载该外边缘项目。
- 主服务器修改项目归属或启停状态后，边缘在同步到位和 reload 后按新归属显示。
- 对空 `edge_instance_id` 真实项目启用严格模式时，边缘不加载并产生可诊断日志。

性能和回归条件：

- 构造至少 8 个项目、数千级变量的全同步库，验证边缘变量列表和工位页面不会因为其他边缘变量而卡顿。
- 工位页切换项目时，卡片、右侧表格、报警、历史和当前检测任务都按项目隔离。
- 检测运行中的显示仍以冻结快照为准，不被项目配置同步变更或 runtime draft 影响。
- 现有通知中心、报表生成、runtime draft、watched STRING 启动检测链路不能因为项目边界收敛退化。
