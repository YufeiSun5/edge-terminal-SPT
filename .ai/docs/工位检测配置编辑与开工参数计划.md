# 工位检测配置编辑与开工参数计划

更新时间：2026-06-22 16:22 Asia/Shanghai

身份：`frontend-ai`

## 背景

新平台工位页已经补回“配置参数”入口，但当前只是检测配置预览和按工位前端暂存：可以选择标准、查看上下限、在未运行状态下影响显示和开始弹窗默认值；还不能在工位页直接修改检测项，也没有把“开工前参数”和 PLC 下设计划纳入同一个用户路径。

用户最新要求把旧 Vue 里配置相关能力完整调研后再规划：检测配置不只是浏览，还要能修改启用/不启用、上下限；同时旧配置中的“吸入口表面积”要移出检测配置，放到开始检测时的参数里，它是一个单值参数，需要下设给 PLC。

## 旧 Vue 调研结论

旧工位页 `runzhong/frontend_V3/src/components/InspectionScreen/InspectionScreen00.vue` 右侧动作区包含“配置 / PID / 开始 / 报警 / 结束”等工作流。“配置”打开 `DataConfig.vue`，“开始”打开 `ConfirmStartDialog.vue`。

`runzhong/frontend_V3/src/components/common/DataConfig.vue` 的“检测配置”弹窗能力：

- 选择 `config_name` 后加载该配置下的检测项。
- 每个普通检测项可编辑 `min_qual`、`max_qual` 和 `isDelete`。
- `isDelete=true` 在旧 UI 上表示“检测”，`false` 表示“不检测”。
- 支持“一键提交所有修改”。
- 支持“一键切换检测”，但只作用于普通范围检测项。
- “使用此配置”会连续调用旧接口 `/api/opc-write/publish`：
  - 写 `{ name: '检测配置', value: config_name }`
  - 写 `{ name: '实装配置标志位', value: 1 }`

旧管理页 `runzhong/frontend_V3/src/components/DataConfigManagement.vue` 对“吸入口表面积”做了特殊处理：

- 它出现在检测配置列表中，但不是范围检测项。
- UI 单独显示“表面积设定值”，只编辑一个 `min_qual` 数值，单位 `m²`。
- 保存时强制 `max_qual = min_qual`，且 `isDelete = true`。
- 一键检测开关、最小值/最大值列和普通上下限逻辑都排除它。
- 报表 `getEXReport.vue` 也把它作为单值写入 `H12`，注释明确“吸入口表面积只有一个值”。

旧 `ConfirmStartDialog.vue` 的开始动作只写基础信息和开始触发：

- 写 `客户名称 / 出厂编号 / 机型`
- 写 `检测开始触发标志位 = 1`
- 没有单独处理“吸入口表面积”，说明旧系统是把这个值临时塞在检测配置/报表配置中，而不是清晰的开工参数模型。

## 新平台现状

新平台已经有正式检测标准模型：

- `desktop/src/features/detection-config/DetectionConfigPage.tsx` 支持检测标准列表、详情、创建、更新和替换检测项。
- 标准项字段已覆盖 `check_enabled`、`alarm_enabled`、`store_enabled`、`limit_l`、`limit_h`、`limit_ll`、`limit_hh`、`check_cycle_ms`、`quality_policy` 等。
- `desktop/src/features/station-operation/StationOperationPage.tsx` 目前的“配置参数”弹窗只是预览和前端暂存，还没有编辑/保存标准项。

后端任务流已经具备开工参数和 PLC 下设基础：

- 默认任务流 `builtin.write_control_variables` 可先执行 `plc_writes`。
- `builtin.start_detection_run` 已接受并冻结 `process_params`、`plc_writes`、`custom_items`、`report_request`、配置版本和配置 hash。
- `TaskFlowExecutor.controlWriteValue` 支持 `value_from`，可从 `process_params.inlet_area_m2` 取值。
- `StartDetectionTaskWithOptions` 会把 `process_params` 和 `plc_writes` 写入本次检测的 `custom_config_json`，用于追溯和报表。

当前缺口主要在前端工位页：

- 开始检测请求尚未把 `process_params` 和 `plc_writes` 放进 task request。
- 工位“配置参数”弹窗还不能编辑 `check_enabled`、上下限、报警/存储开关，也不能保存为检测标准版本。
- PLC 预加载还没有产品化入口，旧 Vue 的“使用此配置”是直接写 OPC；新平台应走后端受控写变量/任务流，不应由页面直连旧 OPC。

## 目标模型

检测配置和开工参数必须拆开。

检测配置用于描述“检测哪些变量、怎么判定”：

- 是否检测：`check_enabled`
- 是否报警：`alarm_enabled`
- 是否入库：`store_enabled`
- 上下限：`limit_l / limit_h`
- 可选高级限值：`limit_ll / limit_hh`
- 判定策略：`quality_policy / check_cycle_ms / violation_hold_ms / recover_hold_ms`

开工参数用于描述“本次检测需要带入和下设的单值/工艺参数”：

- `process_params.inlet_area_m2`：吸入口表面积，单位 `m²`
- 未来可能扩展工装编号、环境修正参数等
- 这些值随本次检测冻结，用于 PLC 下设、报表和历史追溯

“吸入口表面积”迁移规则：

- 新 UI 不再把它作为普通检测标准项展示和编辑。
- 加载旧配置时，如果发现名为“吸入口表面积”的配置项，可把 `min_qual` 或 `limit_l` 迁移/提示为 `process_params.inlet_area_m2` 默认值。
- 保存新检测标准时，不再写入名为“吸入口表面积”的检测项。
- 报表取值从 `process_params.inlet_area_m2` 来，不再依赖检测标准项的 `min=max` 伪字段。

## 前端方案

第一步改造工位页“配置参数”弹窗，定位为“当前工位检测配置编辑/预加载”。

弹窗建议分三段：

1. 配置选择
   - 选择已有检测标准。
   - 显示作用域：本项目 / 项目组 / 全局。
   - 显示版本、hash、更新时间。
   - 支持“复制为当前工位草稿”，避免直接改共享配置。

2. 检测项编辑
   - 表格显示项目、数值、下限、上限、优化系数、结果。
   - 可编辑：检测启用、报警启用、存储启用、下限、上限。
   - 高级项折叠展示：下下限、上上限、死区、持续判定时间、恢复时间。
   - 修改后只影响草稿；未保存前不改变后端标准。

3. 开工参数
   - 显示并编辑“吸入口表面积”，字段为 `inlet_area_m2`，单位 `m²`。
   - 该字段不参与检测项一键启用/禁用。
   - 可显示 PLC 下设映射预览，例如 `value_from = process_params.inlet_area_m2`。
   - PLC 变量名或 `var_id` 未确认前只做配置预览和启动 payload 生成，不硬编码现场点位。

按钮语义：

- “暂存到当前工位”：只存在前端状态或后续工位草稿接口中，影响未运行显示和开始弹窗默认值，不启动检测。
- “保存为检测配置版本”：调用检测标准 API 保存 `standard/items`，产生新版本/hash。
- “预加载到 PLC”：如果现场需要不启动检测也下发配置/参数，应通过后端受控接口或任务流触发 `write_control_variables`；第一版没有后端接口时先不做直接写入。
- “开始检测”：进入开始弹窗，使用当前草稿/标准版本和开工参数生成正式 task request。

开始检测弹窗需要补充：

- `inlet_area_m2` 输入项，默认取当前工位草稿。
- 提交时生成：
  - `process_params: { inlet_area_m2: <number> }`
  - `plc_writes: [{ var_id 或 var_name: <待确认>, value_from: 'process_params.inlet_area_m2', value_type: 'number', wait_ack: true }]`
- 同时保留标准字段：`standard_id / config_enabled / config_code / config_name / config_version / config_hash`。

多工位处理：

- 草稿按 `project_id` 保存，AC-01 和 AC-02 互不串。
- 未运行时，监测表上下限可显示草稿值；运行中必须优先显示本次运行冻结标准。
- 如果用户切换工位，开始弹窗默认加载对应工位草稿，而不是上一个工位的参数。

## 后端/API 方案

第一版尽量复用现有能力：

- 检测标准保存继续使用现有 `detection-standards` 和 `replaceDetectionStandardItems` 能力。
- 开始检测继续通过 watched STRING 任务请求变量触发任务流。
- `process_params`、`plc_writes` 直接随 task request 进入已有默认任务流。

需要确认或补齐的点：

- `DetectionRunStartPayload` 前端类型需要补 `process_params` 和 `plc_writes`。
- 工位开始请求构造需要把开工参数和 PLC 下设计划写入 JSON。
- “预加载到 PLC 但不启动检测”如果必须产品化，应由后端提供受控动作，例如专用任务请求 `command: 'write_control_variables'` 或 edge-control 包装接口。
- 不能恢复旧 Vue 由页面直接调 `/api/opc-write/publish` 的方式；新平台页面不能绕过后端审计、权限和变量写 service。

PLC 映射待确认：

- “吸入口表面积”在当前 PLC/变量表里的正式 `var_id` 或 `var_name`。
- 精度、单位、合法范围。
- 是否需要 ACK、ACK 变量是哪一个、超时时间。
- 是否要在开工前先写一次，还是只在开始任务流中写入即可。

## 数据兼容与迁移

旧数据兼容策略：

- 老配置里仍可能存在“吸入口表面积”项；新 UI 加载时应识别并迁移为开工参数默认值。
- 新保存的检测标准应过滤该项，不再继续扩大历史兼容债。
- 历史任务和旧报表保持只读兼容，不回写修改。

报表策略：

- 新报表模板优先读取 `params.inlet_area_m2` 或 `process_params.inlet_area_m2`。
- 如果历史任务没有该参数，可回退读取旧检测配置项“吸入口表面积”的 `min_qual/limit_l`。
- 回退只用于历史兼容，不作为新任务写入路径。

## 施工阶段

阶段 A：字段和映射确认

- 确认 PLC 变量名/`var_id`、ACK 策略、合法范围。
- 确认“吸入口表面积”报表模板字段读取路径。
- 确认是否第一版必须支持“不开始检测，只预加载到 PLC”。

阶段 B：工位配置弹窗升级

- 把当前“检测配置预览”升级为可编辑草稿。
- 支持检测启用、报警启用、存储启用、上下限编辑。
- 识别并隐藏/迁移旧“吸入口表面积”检测项。
- 草稿按 `project_id` 隔离。

阶段 C：保存检测标准版本

- 保存时调用现有检测标准 API。
- 保存 payload 不包含“吸入口表面积”。
- 保存成功后刷新标准列表，更新当前工位草稿的版本/hash。

阶段 D：开始检测参数接入

- 开始弹窗加入 `inlet_area_m2`。
- task request 增加 `process_params` 和 `plc_writes`。
- 运行中快照页可看到冻结的开工参数和下设计划。

阶段 E：PLC 预加载

- 如果阶段 A 确认需要，增加“预加载到 PLC”按钮。
- 优先使用现有任务流 `write_control_variables` 或后端 edge-control 包装接口。
- UI 显示写入结果、失败原因和最近下发时间。

阶段 F：报表和历史兼容

- 报表参数编辑和 Excel 生成读取 `inlet_area_m2`。
- 历史快照 tab 展示本次检测开工参数。
- 对旧任务做只读回退显示。

## 验证计划

前端单元/组件：

- 旧检测项“吸入口表面积”能转成 `process_params.inlet_area_m2` 默认值。
- 保存标准时过滤“吸入口表面积”。
- 切换 AC-01/AC-02 时草稿互不影响。
- 开始 payload 包含 `process_params` 和 `plc_writes`。

后端/任务流：

- `value_from: process_params.inlet_area_m2` 能解析并写入变量。
- 开工后 `custom_config_json` 冻结 `process_params/plc_writes`。
- 标准项上下限和启用状态正确冻结到检测任务。

浏览器 smoke：

- 工位页打开“配置参数”，能编辑上下限和启用状态。
- 暂存后未运行监测表显示草稿上下限，但不创建检测任务。
- 开始弹窗显示吸入口表面积，提交后任务正常 running。
- 运行中页面优先显示冻结标准，而不是当前草稿。

现场验收：

- 不开始检测时，如果执行“预加载到 PLC”，PLC 侧能读到吸入口表面积且任务没有创建。
- 正式开始检测时，PLC 下设和检测任务创建在同一次任务流中完成。
- 报表能显示本次 `inlet_area_m2`，不再依赖检测标准里的“吸入口表面积”项。

## 风险与待确认

- PLC 点位名称/`var_id` 未确认，不能在前端硬编码。
- 共享检测配置直接编辑可能影响同项目组其他工位，第一版应优先使用“复制为草稿/保存新版本”。
- 旧 `isDelete=true` 表示检测，新平台是 `check_enabled=true`，迁移时不能按字段名直译。
- `check_cycle_ms` 不能再被误解为历史入库周期，入库周期仍由 storage route 控制。
- 如果用户要求“配置预览即写 PLC”，必须先确定后端审计和权限链路，不能恢复旧页面直连 OPC。
